# ADR 0001: Stack and hosting

- Status: accepted
- Date: 2026-11-19

## Context

Shetu needs a working public demo for the preliminary round on 20 Nov 2026 and a production-minded build for the final on 26 Dec. Judges score technical execution ("well-structured AI-native design", "production-grade engineering maturity") and scalability. The AI work is structured extraction and planning with strict validation, and the product logic is a set of deterministic rules.

## Decision

| Concern | Choice | Why |
|---|---|---|
| API | Python 3.12, FastAPI, Pydantic v2 | The model SDKs are Python-first; Pydantic gives one schema language for API contracts and model outputs |
| Persistence | PostgreSQL via SQLAlchemy 2, Alembic migrations | Industry standard; relational data with clear constraints. SQLite for local runs and tests |
| Packaging | uv with a lockfile | Fast, reproducible installs in CI and Docker |
| Quality | Ruff, strict mypy, pytest | Typed, linted and tested on every push |
| Web | Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4 | Mainstream React framework with first-class Vercel hosting |
| Client data | TanStack Query, openapi-fetch with types generated by openapi-typescript | End-to-end types from the FastAPI OpenAPI spec; CI fails on drift |
| AI | Own gateway over google-genai and anthropic SDKs | Swap providers with one setting; no agent framework hiding control flow |
| Hosting | Vercel (web), Render with Docker (API), Neon (Postgres) | Managed, free to start, Git-based deploys |
| CI | GitHub Actions; Dependabot | Standard for GitHub repos |

## Consequences

- Two languages in one repo, held together by the generated API contract.
- Render's free tier sleeps when idle; warm the API before a live demo, or move to a paid instance for the final.
- No agent framework or vector database. If retrieval over policy documents is added later (for example per-country leave rules), it gets its own ADR.
